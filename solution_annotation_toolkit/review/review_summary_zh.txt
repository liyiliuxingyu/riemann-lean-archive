四、字段与语义人工复核

- N、L、E 分别表示名称表、宇宙层级表、表达式表，@line 才是原文件行号。
  Name 0 为匿名名称，Level 0 为零层级；表达式 0 是实际定义的表达式。
- bvar 表示 de Bruijn 绑定距离；proj.idx 是从零开始的字段序号，均没有
  误当成表达式表引用。人工数据使用大于 2^53 的整数验证这一点。
- levelParams 引用名称表，const.us 引用宇宙层级表，未混用。
- axiom 明确无本行证明体；thm 保留证明项引用；opaque 仍保留给定值；
  def 的 hints 与顶层 opaque 声明性质明确区分。
- def.safety 的 partial 没有被误译成数学证明只完成一部分；all 没有
  被称为全部依赖清单。
- letE.nondep 没有被误译为主体不使用变量。
- inductive 的类型、构造器、递归器与每项计算规则均逐项说明；
  isReflexive 没有被误译为二元关系的自反律；k 被标为 K-like 归约标记。
- 长 natVal 的原始十进制字符串完整保留，注释中若截短显示会明确说明；
  字符串内容只作为数据展示。

五、审查期间发现并修复的问题

最初候选二进制在真实前缀上触发 SIGSEGV。引擎作者修复了 simdjson
临时对象的循环生命周期问题，并修正多字节中文标点使用 char 字面量的
问题；之后独立运行成功且通过完整 UTF-8 检查。

独立审查另发现 regular 未限制 UInt32 上界，以及 mdata.data 未检查
各值为字符串。引擎作者已修复。边界回归检查确认 regular=4294967296
与 mdata 中非字符串值均在准确行号报错，且不产生成功摘要；详见
invalid_boundary_review.json。该两项回归发生在最终冻结前的修复版本，
相关检查逻辑在最终源代码中保留。

最初注释会直接保留 Unicode U+2028/U+2029，在某些阅读器中呈现换行。
最终 quote 实现已转义 C1 字符（含 U+0085/NEL）、DEL、U+2028/U+2029，
同时保持原始 JSON 原文不变。引擎作者报告最后转义修复已复测通过。
本独立复核随后又对最终冻结二进制运行了上述三组测试，独立确认所用
样本内的 U+2028/U+2029 已转义。独立样本没有包含 U+0085；对该字符的
结论限于最终实现审读及引擎作者的复测报告，不另称独立实测覆盖。

六、解释与验证的边界

本次检查未重新下载文件、未读取或写出完整 61 GB 解压文件、未运行全量
Lean 内核。全部 147,492 行的“实际前缀测试”不能替代完整导出文件的
输入哈希核验、全量逐行处理统计与输出分卷核验。最终完整性结论应以
全量处理任务最终的摘要和分卷清单为准。

本引擎对未知或不符固定格式的记录会立即报错停止，并报告位置；它没有
对未知记录继续猜测语义。遇到这种错误时不能把未完成输出称为完整结果。

逐行中文说明解释的是 NDJSON 字段和共享对象引用，不能据此宣称完成了
目标猜想的人类可读数学证明，也不能替代证明内核对类型与证明项的检查。
